# 真机实验环境搭建指南（one_leg，Stage 3–5）

这份指南告诉你怎样摆好桌子、零件、背景、灯光和两台相机，让真实场景和仿真对得上。只有对得上，下面三步才能顺利进行：

- **Stage 3**：用你的相机参数重新渲染 D_synth。
- **Stage 4**：采集 D_real。
- **Stage 5**：部署并评估 π_real。

机器人控制本身（FR3 + Polymetis、teleop 脚本）见 [FR3_ORIGINAL_CODE_TELEOP_TEST.md](FR3_ORIGINAL_CODE_TELEOP_TEST.md) 和 [REAL_ROBOT_FR3_GUIDE.md](REAL_ROBOT_FR3_GUIDE.md)。各 stage 的命令见 [IMPLEMENTATION_GUIDE.md](IMPLEMENTATION_GUIDE.md)。

文中所有数值都来自代码：仿真场景在 [furniture_sim_env.py](../furniture-bench/furniture_bench/envs/furniture_sim_env.py)，渲染场景在 [isaac_lab_rerender.py](../src/sim2real/isaac_lab_rerender.py)，零件初始位姿在 [config.py](../furniture-bench/furniture_bench/config.py)。论文本身没有给出场景尺寸。

---

## 0. 核心原则

1. **一切以机器人基座坐标系为准。** 策略的状态和动作都是指尖在基座系下的位姿，仿真里的零件、固定条和相机也都定义在这个坐标系里。真实场景只要在基座系下和仿真一致，桌子在房间里放在哪里都无所谓。
2. **相机要对齐到毫米级，而且装好以后不能再动。** 渲染时对相机位姿做的随机化很小：前视相机的位置标准差 2.5 mm、角度 0.5°，腕部相机 0.75 mm、0.25°（`random_camera_pose`，[isaac_lab_rerender.py:554](../src/sim2real/isaac_lab_rerender.py#L554)）。所以渲染相机必须和真实相机**仔细对齐**（§7），不能"量个大概"。
3. **Stage 4 和 Stage 5 用同一个场景。** 桌子、背景、灯光、相机、固定条的标称位置在采集和部署之间都不能变。
4. **物理上必须和仿真一致的，与只需要和渲染一致的，要分开。** D_synth 的轨迹是仿真物理跑出来的，渲染（Stage 3）只决定图像长什么样：
   - **必须物理匹配**（渲染改不了）：零件和挡条在基座系下的位置，零件所在平面和安装面等高，桌面平整。
   - **只需要渲染跟着真机改**：桌子的大小和颜色、背景、灯光、相机位姿（§3.1、§7.0）。真实场景定下来以后，把渲染器改成和它一样。

| Stage | 对场景的要求 |
|---|---|
| 3 渲染 D_synth | 渲染器里的相机内参、外参与真实相机一致；真实零件和背景的外观与渲染近似（渲染时会随机化颜色和光照） |
| 4 采集 D_real | 零件和固定条的初始位置落在仿真 "low" 随机范围内（§5.3）；相机与 Stage 3 用的完全相同 |
| 5 部署 | 和 Stage 4 完全相同的场景；评估点取自同一个随机范围 |

## 3. 桌子和机器人

1. **高度**：桌面要和 FR3 安装面平齐，误差控制在 5 mm 以内。如果 FR3 装在独立底座上，就调桌子高度（加垫或用升降桌），不要改仿真。桌面高度不对，策略学到的 z 方向动作在真机上就会抓空或撞桌。
   - 常见情况是 FR3 装在一块铝底板上，底板再固定在桌上。这时"安装面"是**底板顶面**，比桌面高出一个底板厚度（常见 1–2 cm），零件直接放桌上就低了这么多。解决办法见 §3.1。
2. **位置**：仿真里机器人基座在桌子 y 方向的中线上，离桌子后缘约 35 cm，基座系下的桌面范围大约是 x ∈ [−35, 95] cm，y ∈ [−40, 40] cm。真机**不需要**照搬这个桌子，但零件布局（§5.1）相对基座的位置是固定的，不能整体平移或旋转。所以要保证你的桌子在基座前方（+x）能支撑到约 77 cm。FR3 底座接线口那一侧是 −x，对面是 +x。
3. **工作区清空**：x ∈ [25, 80] cm、|y| ≤ 30 cm 范围内只放 one_leg 的零件和挡条。
4. **在桌上画出基座坐标系**：§4.1 介绍用机器人自己当画线工具，这是最准的办法。先画一条 x 轴线（y = 0），再在 x = 30、40、50、60、70 cm 处画刻度。
5. **检查桌面高度**：用 §4.1 的脚本让指尖在工作区四角和中心各碰一次桌面，读出的 z 都应该在 0 ± 5 mm 以内。

### 3.1 桌面不平整或尺寸不够时（例如铝型材桌）：铺一块台面板

如果桌面是带沟槽的铝型材、尺寸比 130 cm 小，或者机器人装在一块高出桌面的底板上，做法是**铺一块平整的哑光台面板，再让渲染器去匹配这块板**（§3.2）。只在渲染里换一个沟槽桌面模型不行，原因有三个：

1. **高度**：零件要放在和安装面等高的平面上。策略输出的是绝对位姿，零件低 1–2 cm，抓取和插入的高度就会整体偏掉。要在数据侧修正，得改 `ROBOT_HEIGHT` 重新生成 D_synth，再重训 base policy 和残差 RL，代价太大。
2. **平整**：桌腿截面只有 3 cm，放在沟槽上可能卡进槽里或歪斜，推动和插入时的接触也和仿真的光滑平面不一样。
3. **外观**：渲染里的桌面是一块纯色漫反射灰，没有纹理（§5.2）。黑色阳极氧化型材有条纹，高光还会随灯光和视角移动，很难渲染到对得上的程度。

**板子要覆盖的区域**（基座系，cm；按 §7.1 的标称前视相机位姿计算，换了相机位姿要重新算）：

| | x 范围 | y 范围 | 说明 |
|---|---|---|---|
| 硬性最小 | 25 → 77 | −28 → +28 | 零件和挡条加上 §5.3 的随机范围，再留 5 cm 余量 |
| 推荐 | 15（底板前缘）→ 80 | −45 → +35 | 覆盖前视相机在 x ≥ 14 处能看到的全部桌面 |

- **左右不对称**是因为前视相机在 y = −6.5。策略能看到的区域（§7.1）投到桌面上：x = 69 处是 y −26.5 ~ +13.5，x = 37 处是 −37.5 ~ +24.5，x = 14 处是 −45 ~ +32，x = 0 处是 −50 ~ +37。
- **前视相机下面不需要桌子。** 这块区域的下沿正好在 x ≈ 69，画面看不到 x > 71 的桌面。相机在 x = 112，用型材立柱或夹臂架过去就行。
- **板子以外的区域**用黑色哑光布盖住，包括机器人底板（剪个孔套过底座）和机器人身后一直到背景布（x = −50）。这些地方在前视画面里看得到，渲染里也会设成黑色（§3.2），和黑色背景连成一片。
- 旁边别的桌子、线缆、标定板等杂物收掉或盖住。

**板子的要求**：
- **厚度**：等于底板顶面到桌面的高度，误差 ≤ 3 mm。用卡尺在底板四周量几处，不够就用薄板或垫片补。装好后照 §3 第 5 步复查。
- **刚度和固定**：15–18 mm 的 MDF、多层板或者铝板。型材桌可以用槽里的 T 型螺母加压板固定。插入时机器人会往下按，板子不能翘也不能晃。挡条直接固定在板上。悬空部分不超过约 10 cm。
- **表面**：哑光、颜色均匀、不要木纹，选中灰色（sRGB 大约 110–150）。这样白色 PLA 零件和板子对比明显，板子和黑色背景也分得开。可以贴哑光灰色 PVC 或防火板贴面，也可以刷哑光漆。

### 3.2 渲染器跟着台面板改（Stage 3）

都在 [isaac_lab_rerender.py](../src/sim2real/isaac_lab_rerender.py) 里改。下面的代码是草稿，没有运行过。

1. **桌面几何**：改子节点 `/World/Table/table2` 的缩放和平移，让它和板子一样大、位置一致，顶面保持在 world z = 0.415。**不要改父节点 `/World/Table` 的缩放**（[isaac_lab_rerender.py:636](../src/sim2real/isaac_lab_rerender.py#L636)），因为房间的墙和灯（`/World/Table/Lights/*`）也挂在它下面，改了光照会变。
   ```python
   # 放在 table_view.set_local_scales(...) 之后
   from pxr import Gf
   BOARD = dict(x0=0.15, x1=0.80, y0=-0.45, y1=0.35)   # 板子在基座系下的范围，单位 m
   t2 = prim_utils.get_prim_at_path("/World/Table/table2")
   cx, cy = (BOARD["x0"] + BOARD["x1"]) / 2, (BOARD["y0"] + BOARD["y1"]) / 2
   # 网格本身 1.3 × 0.8 m，父节点已经缩放了 1.7 × 1.35；world = 基座 + (-0.30, 0, 0.415)
   t2.GetAttribute("xformOp:scale").Set(Gf.Vec3f((BOARD["x1"] - BOARD["x0"]) / 1.3 / 1.7,
                                                 (BOARD["y1"] - BOARD["y0"]) / 0.8 / 1.35, 1.0))
   t2.GetAttribute("xformOp:translate").Set(Gf.Vec3d((cx - 0.30) / 1.7, cy / 1.35, 0.4))
   ```
2. **板外的黑布**：加一块很大的黑色哑光平面（比如 3 × 3 m 的薄长方体），顶面比 0.415 低 1–2 mm，避免和板子表面闪烁重叠（z-fighting）。材质的 `diffuse_color_constant` 取接近 0，`reflection_roughness_constant` 取 1.0。
3. **颜色**：用 RealSense 拍一张板子，调 `Material_010` 的 `diffuse_color_constant`（[table_room.usda](../src/sim2real/assets/furniture/mesh/usd/table_room.usda) 第 209 行，原值 0.443 灰）和 `reflection_roughness_constant`（原值 0.3，哑光板大约 0.7–0.9）。调到渲染图里板子的平均像素值和真机相差 10 个灰度以内。
   - `RandomizationHelper` 在初始化时读这个颜色作为标称值，所以要改 usda 文件，或者在创建 `RandomizationHelper` 之前改。
   - 颜色随机化保持 `--table-random base`，它就会在新颜色附近小幅抖动。`full` 模式会把颜色随机到 0.5–1.0 之间，覆盖掉你调好的值。
4. **对齐**：然后按 §7.4 叠图对齐。板子的直边正好是很好的对齐参照。

## 4. 用机器人做尺子（推荐）

手工测量基座中心很难测准，直接让指尖去点目标位置要准得多。下面的脚本需要先装好 Franka Hand，并且 Polymetis 服务器已经启动（[FR3_ORIGINAL_CODE_TELEOP_TEST.md](FR3_ORIGINAL_CODE_TELEOP_TEST.md)）。

### 4.1 标记点脚本（草稿，未在真机上验证）

```python
# scratch/mark_points.py — 在 polymetis 环境里运行；手里始终握着使能器
import numpy as np, torch
from polymetis import RobotInterface

TIP = 0.1034                                   # 法兰 → 指尖（teleop_sm.py 里的 convert_wrist2tip）
DOWN = torch.tensor([1.0, 0.0, 0.0, 0.0])      # 法兰朝下的四元数 (xyzw)
robot = RobotInterface(ip_address="localhost") # 和 teleop 用的是同一个服务器

# 要标记的点（基座系，单位 m）：x 轴刻度 + 零件标称中心（§5.1）
points = [(0.30, 0.0), (0.40, 0.0), (0.50, 0.0), (0.60, 0.0), (0.70, 0.0),
          (0.5415, 0.0),                       # 桌面中心
          (0.3715, -0.20), (0.3715, -0.12), (0.3715, 0.12), (0.3715, 0.20),   # 桌腿原点
          (0.6815, 0.0), (0.6065, -0.175), (0.6065, 0.175)]                  # 挡条中心

for x, y in points:
    for z_tip in (0.05, 0.005):                # 先到 5 cm 高，再降到 5 mm 高
        robot.move_to_ee_pose(torch.tensor([x, y, z_tip + TIP]), DOWN, time_to_go=4.0)
    input(f"在指尖正下方标记 ({x*100:.1f}, {y*100:.1f}) cm，按回车继续")
    robot.move_to_ee_pose(torch.tensor([x, y, 0.05 + TIP]), DOWN, time_to_go=2.0)
```

`move_to_ee_pose` 是 Polymetis 自带的接口，内部先算 IK，再做关节插值。第一次运行时把 `time_to_go` 调大，人站在急停旁边。

### 4.2 读取当前指尖位置

用 SpaceMouse 把指尖移到某个点上（比如相机支架的某个角），再读它的坐标。有两个办法：
- 在你自己的 `teleop_sm_fr3.py` 里取消 `print(f"EE xyz: ...")` 那一行的注释。原始的 `teleop_sm.py` 里有这一行，被注释掉了。
- 或者单独运行下面的脚本：

```python
import numpy as np
from scipy.spatial.transform import Rotation as R
from polymetis import RobotInterface
r = RobotInterface(ip_address="localhost")
p, q = r.get_ee_pose()
T = np.eye(4); T[:3, :3] = R.from_quat(q.numpy()).as_matrix(); T[:3, 3] = p.numpy()
off = np.eye(4); off[2, 3] = 0.1034; off[:3, :3] = R.from_euler("z", -45, degrees=True).as_matrix()
print("tip (cm):", ((T @ off)[:3, 3] * 100).round(1))
```

## 5. 零件和固定条

### 5.1 标称布局（基座系）

low、med 用的是同一组标称位置，差别只在 §5.3 的随机偏移。坐标原点在机器人基座中心，x 朝前（朝前视相机），y 朝机器人左侧，z 朝上，z = 0 是零件所在的平面。数值由 [config.py](../furniture-bench/furniture_bench/config.py) 的 `reset_pos[0]` / `reset_ori[0]`、[furniture_rl_sim_env.py:316-338](../furniture-bench/furniture_bench/envs/furniture_rl_sim_env.py#L316-L338) 和各零件的 `.obj` 模型算出。

**位置和占地范围**（单位 cm）：

|---|---|---|---|---|---|---|
| **桌面** `square_table_top` | 54.15 | 0 | 1.56 | 46.02 ~ 62.27 | −8.13 ~ +8.12 | 0 ~ 3.12 |
| leg1 | 37.15 | −20 | 1.5 | 31.52 ~ 40.27 | −21.56 ~ −18.56 | 0 ~ 3 |
| leg2 | 37.15 | −12 | 1.5 | 31.49 ~ 40.29 | −13.46 ~ −10.46 | 0 ~ 3 |
| leg3 | 37.15 | +12 | 1.5 | 31.52 ~ 40.27 | +10.44 ~ +13.44 | 0 ~ 3 |
| **leg4**（要装配） | 37.15 | **+20** | 1.5 | 31.52 ~ 40.27 | +18.56 ~ +21.56 | 0 ~ 3 |
| **前挡条** `obstacle_front` | 68.15 | 0 | 1.5 | 67.15 ~ 69.15 | −17.5 ~ +17.5 | 0 ~ 3 |
| **侧挡条** `obstacle_left` | 60.65 | +17.5 | 1.5 | 52.15 ~ 69.15 | +16.5 ~ +18.5 | 0 ~ 3 |

**朝向**：

- **桌面**：边和坐标轴平行，**底面（有四个桌腿孔）朝上**。四个孔的中心在 (48.53, ±5.62) 和 (59.77, ±5.62)。基座系四元数 xyzw 是 `[0.5, -0.5, -0.5, 0.5]`。
- **桌腿**：平躺，长轴沿 x 方向。**螺纹端朝机器人**，螺纹段大约在 x 31.5 ~ 34，直径约 2.4 cm；方身截面 3 × 3 cm，平端在 x ≈ 40.3，朝前视相机。四条腿的基座系四元数 xyzw 都是 `[0.5, 0.5, -0.5, 0.5]`。
- **挡条**：边和坐标轴平行。前挡条 35 × 2 × 3 cm，沿 y 方向；侧挡条 17 × 2 × 3 cm，沿 x 方向。

**用尺子复查的间距**（标称位置下，单位 cm）：

| 间距 | 数值 |

| 桌面前缘 → 前挡条内侧面 | 4.88 |

**和数据里的坐标对应**：`parts_poses` 和 `config.py` 用的是 AprilTag 坐标系，换算到基座系（单位 m）是 `x = 0.3015 + y_tag`，`y = x_tag`，`z = −z_tag`。比如 leg4 的 `reset_pos` 是 `[0.20, 0.07, -0.015]`，对应基座系 (0.3715, 0.20, 0.015)。

几点说明：
- **要装配的是 leg4**，即 y = +20 cm、机器人左侧那条（`OneLeg.should_be_assembled = [(0, 4)]`）。仿真里 leg4 插进四个孔的任何一个都算成功（`assembled_rel_poses[(0, 4)]`）。另外三条腿也要摆上，因为渲染场景里五个零件都在（`--num-parts 5`）。

### 5.3 初始位置的随机范围（low 和 med）

真机采集和评估都用 low，med 的数值只作参考。

| leg3 | −0.4 ~ +0.4 | −0.7 ~ +0.6 | ±18° | −2.3 ~ +2.6 | −3.0 ~ +2.5 | ±47° |

## 7. 相机安装和对齐

### 7.0 相机位置可以自己定

**可以自己定，只要渲染里的相机和真机一致。** π_real 是从零训练的视觉策略，训练数据是 D_synth 的渲染图加 D_real。base policy 和残差 RL 都只用状态，不看图像。所以相机位姿不会写进前面任何一个阶段，§7.1 和 §7.2 的标称位姿只是作者的选择。

硬约束：
1. **Stage 4 开始前定死。** D_real、Stage 3 的渲染、Stage 5 的部署必须用同一套相机位姿。采完数据再动相机，已采的数据就作废了（§9.1）。
2. **安装牢固、对齐准确。** 渲染时的相机随机化只有前视 2.5 mm / 0.5°、腕部 0.75 mm / 0.25°（§0）。前视相机用螺丝固定在型材框架上，腕部相机刚性固定在手上，然后按 §7.4 对齐。
3. **渲染里没有的东西，尽量别让相机看见。**
   - 渲染器用的是 Isaac Lab 自带的 `FRANKA_PANDA_CFG`（[isaac_lab_rerender.py:701](../src/sim2real/isaac_lab_rerender.py#L701)），是 Panda 的模型。FR3 的外观和它不一样，比如腕部的按键。
   - 渲染里也没有腕部相机的支架。
   - 线缆、机器人底板、玻璃围栏、窗户、显示器、人，这些在渲染里都没有。
   - 所以选位置时，要让桌面和零件占画面的大头，桌面以外是黑布，机械臂占的画面尽量少。

**前视相机怎么放：**
1. **要看的东西都落在策略能看到的区域里，四周留余量。**
   - 策略能看到的区域是原图 x ∈ [96, 544]、y ∈ [16, 464]（§7.1）。训练时还会在这里面做随机裁剪，所以再留 20–30 px 的边。
   - 必须完整落在里面的有：U 形固定条加 ±2 cm 随机范围、四条腿和桌面、leg4 插入的那个孔，以及插入时指尖的活动范围。
   - 原版位姿其实很紧。在 x ≈ 60 cm 处，区域右边界只到 y = +16.7 cm，而 +y 侧挡条在 16.5–18.5 cm，前端已经有一部分出了框。上方约 30% 是背景，像素浪费了。
2. **从机器人对面看（原版的方向）。** 机械臂从后面伸向零件，相机在对面看到的是夹爪正面，插入的位置不容易被手臂挡住。可以往 leg4 那一侧（+y）偏一点，让插入的角更清楚，但别偏太多，否则机械臂会横过画面。
3. **俯角比原版大一些，30°–45° 比较合适（原版 21.5°）。** 俯角大一些，桌面和零件占的像素更多，背景和远处杂物更少。但不要接近垂直俯视，插入要靠斜视角看出桌腿离孔还有多高。
4. **距离**：策略能看到的区域对应的视场角大约是 40° × 40°（448 px / fx ≈ 607），在光轴距离 d 处覆盖的宽度约为 0.74 d。要让离相机最近的前挡条（加随机范围约 45 cm 宽）完整入框并留余量，前挡条离相机的距离要 ≥ 约 70 cm。相机到工作区中心一般是 70–90 cm，原版约 73 cm。
5. **避开反光和逆光。** 相机不要对着窗户、玻璃围栏或灯，也不要放在灯光会在板面上反射进镜头的角度。
6. **不挡人，也不挡机器人。** 每条示教之后都要复位零件，相机和支架不要放在人手伸进来的路线上，也要在机器人整个工作空间（包括 home 位姿和插入姿态）之外。

**腕部相机怎么放：**
- **视角**：画面下沿能看到两个指尖，往前能看到被抓的零件和目标孔。原版装在手的 −x 侧、往下倾约 20°（§7.2），可以直接照搬。插入时腕部相机是主要信息来源，一定要能看到孔和桌腿的螺纹端。
- **支架**：用金属件或者壁厚足够的打印件，夹在法兰或手上，不能有任何晃动。支架和相机不能超出夹爪外轮廓太多，不然插入时会撞到挡条或桌面。线缆沿手臂固定好，给 J7 转动留够余量。
- **画面里尽量少出现支架。** 渲染里没有支架，真实画面里支架挡住一角、渲染图那里却是空的，就会产生差异。实在避不开，就在渲染里加一个简单的盒子来代替它。

**定下位置后**：把位姿写进渲染器（§7.4 第 3 步）。如果和标称位姿差得多，§3.1 的台面板覆盖范围也要按新位姿重新算。

### 7.2 腕部相机

**标称位姿**（[isaac_lab_rerender.py:744-751](../src/sim2real/isaac_lab_rerender.py#L744-L751)），在 `panda_hand` 坐标系下：

| 量 | 值 |
|---|---|
| 位置 | (−5, 0, +4) cm：手爪 −x 侧的平面上，沿手指方向偏 4 cm |
| 朝向 | 视线基本沿手指方向（+z），向手指中心内倾约 20° |

`panda_hand` 的原点在法兰中心，坐标轴相对法兰绕 z 轴转了 −45°；z 轴沿手指方向，手指沿 y 方向开合。

安装要点：
- 用 FurnitureBench 的打印支架，装在手爪**背面**（即 −x 侧），镜头朝向指尖。
- 线缆用三根扎带固定在机械臂上，并留出足够余量。关节转到极限时线不能被拉紧，否则相机会被拽偏。
- 在 home 位姿下，画面下方应该能看到两根指尖，前方能看到桌面和零件。
- **装好后把相机和支架的重量加进末端负载。** Desk 里的 Franka Hand 配置（0.73 kg）不包含它们，机器人的重力补偿会因此偏小。

**负载没更新时的现象：** 跑 `communication_test` 时，机械臂到位后在 10 秒零力矩阶段会自己往下掉，而 teleop 看起来正常。这是因为 teleop 用关节阻抗控制，高刚度把误差压小了：关节 4 的 `Kq` 是 100 Nm/rad，1 Nm 的误差只下沉约 0.6°。偏差其实还在，刚度越低越明显，所以采集和部署之前要修好。

**处理方法：**
1. 称出相机加支架的总重 `m_cam`，估计它们相对法兰的重心 `r_cam`。按上面的标称位姿，可以从 `r_cam ≈ (−0.035, 0.035, 0.04)` m 开始，再按实际支架调整。
2. 计算合并后的负载：
   ```
   m_total = 0.73 + m_cam
   CoM     = (0.73 × [-0.01, 0, 0.03] + m_cam × r_cam) / m_total
   ```
3. 在 Desk 的 *Settings → End-Effector* 里更新质量和重心，惯量粗略估计即可。
4. 再跑一次 `communication_test`，手放在急停上，确认机械臂在 10 秒内基本不再下掉。

如果 Desk 改不了配置，以及验证负载的命令，见 [FR3 测试文档 §11.3](4_FR3_ORIGINAL_CODE_TELEOP_TEST.md#113-mount)。

注意：`build_camera_params` 只用到 fx、fy 的平均值，cx 和 cy 没有用上。

**(2) 外参初值**，二选一：
- **测量法**：用 §4.2 读出前视相机镜头附近一点的基座系坐标，用卷尺量高度，用量角器或手机水平仪量俯角，得到一个粗略位姿。
- **手眼标定法（更准）**：在手爪上固定一块 ArUco 或棋盘格标定板，让机器人走 15–20 个姿态，用 `cv2.calibrateRobotWorldHandEye` 求出前视相机在基座系下的位姿（eye-to-hand）。腕部相机用 `cv2.calibrateHandEye` 求出它相对法兰的位姿（eye-in-hand），这时标定板固定在桌上。

**(3) 换算成渲染器的格式。** 渲染器用 Isaac/USD 的相机约定：视线沿 −Z，上方向是 +Y，欧拉角是内旋 "XYZ"。世界坐标 = 基座坐标 + (−0.30, 0, 0.415)。OpenCV 的相机约定是 x 右、y 下、z 前。

```python
import numpy as np
from scipy.spatial.transform import Rotation as R
FLIP = np.diag([1, -1, -1])                       # OpenCV 相机系 → USD 相机系

# 前视：T_base_cam 是 OpenCV 约定下相机在基座系的 4×4 位姿
def front_to_rerender(T_base_cam):
    pos = T_base_cam[:3, 3] + np.array([-0.30, 0.0, 0.415])
    eul = R.from_matrix(T_base_cam[:3, :3] @ FLIP).as_euler("XYZ", degrees=True)
    return pos, eul                               # → 填进 cam_pos 和 R.from_euler("XYZ", ...) 的角度

# 腕部：T_flange_cam 是 OpenCV 约定下相机相对法兰(link8)的位姿；panda_hand = 法兰绕 z 转 -45°
def wrist_to_rerender(T_flange_cam):
    T_hand_flange = np.eye(4); T_hand_flange[:3, :3] = R.from_euler("z", 45, degrees=True).as_matrix()
    T = T_hand_flange @ T_flange_cam
    return T[:3, 3], R.from_matrix(T[:3, :3] @ FLIP).as_euler("XYZ", degrees=True)
```

可以先用标称值验证一下：把渲染器里的前视位姿 `(0.82, -0.065, 0.8)`、`[0, 68.5, 90]°` 反算回来，应该得到视线 ≈ (−0.93, 0, −0.37)，也就是朝 −x、下俯 21.5°。

**(4) 叠图对齐（必做）。** 让真实画面和渲染画面在**完全相同的状态**下对比，反复微调外参，直到二者重合：

1. **选一个参考状态**：取一条仿真 rollout 的 pickle，比如 `$DATA_DIR_RAW/raw/diffik/sim/one_leg/rollout/low/success/` 下的任意一个，把它截短到前 3 步，单独放进一个文件夹：

## 8. Stage 4：采集 D_real

每个 episode 开始前：
1. 机器人回 home 位姿。teleop 脚本会自动执行，并给每个关节加 ±5° 的随机噪声。
2. **复位零件**：从 §5.3 的零件网格里取下一个点，按胶带标记摆好桌面和 leg4，其余三条腿放在标称位置附近。
3. **复位固定条**：按计划取一个固定条网格点（换点时揭开胶带再重新粘好）。
4. 确认灯光一致，画面里没有手、工具或其它杂物，相机没有被碰过。
5. 运行 teleop，完成后按 `t` 保存（`n` 放弃）。

采集计划：
- 论文用了 10–40 条示教。
- 让零件网格和固定条网格的点都被覆盖到，比如零件 9 个点 × 固定条在中心，再加上固定条 9 个点 × 零件在中心。
- 每条示教都要从网格点出发，不要每次都从同一个位置开始。

采完之后：
- 用 [DATA_GUIDE.md](DATA_GUIDE.md) §9 的工具查看视频，确认相机顺序和颜色正常。
- 用 notebook `07_real_vs_sim_state_action_space` 检查**真实动作是否落在仿真动作的分布里**（论文 Fig. 19）。如果没有，最常见的原因是零件或挡条的位置和 §5.1 差得太多，或者桌面高度不对。

## 9. Stage 5：部署和评估

- 场景和 Stage 4 完全相同。部署前先做 §9.1 的相机检查。
- **评估**：按论文的做法做两组，每组 10 次。
  - 第一组只改变零件位置，从零件网格里取点，固定条在中心。
  - 第二组只改变固定条位置，从固定条网格里取点，零件在中心。
  - 每次按阶段记录成功与否：对准角落、抓取、插入、拧紧。
  - 比较不同策略时，使用同一组网格点。

### 9.1 每次开工前检查（约 2 分钟）

1. 机器人移到 §7.4 保存的那组关节角，按对齐时的布局摆好零件。
2. 拍一张前视图，和 `real_front.png` 做差，或者直接叠图看。
3. 如果桌面、挡条这些静止物体的位移超过约 3 像素，说明**相机被动过了**。这时有两个选择：
   - 把相机调回原位，直到叠图重合。
   - 或者重新做 §7.4 并重新渲染。但 Stage 4 已经采集的数据是旧视角下的，混用会降低效果。
4. 腕部相机同样用 `real_wrist.png` 检查。重点看指尖在画面里的位置有没有变。

## 10. 常见问题

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 叠图怎么调都对不上，越调越偏 | 内参没换，或者把 OpenCV 和 USD 的相机约定搞混了 | 检查 §7.4 (1)，以及 (3) 里的 `FLIP` |
| 远处对上了，近处没对上 | 平移或焦距不对 | 先确认内参，再调相机的前后距离 |
| 真实动作的分布比仿真偏高或偏低 | 桌面不在安装面高度 | §3 第 1、5 步 |
| 桌腿放在桌上会歪、会卡进槽里，或者零件比仿真低一截 | 桌面带沟槽，或者机器人装在高出桌面的底板上 | §3.1 铺台面板 |
| 渲染图里桌面和真实画面的灰度、亮暗差很多 | 渲染材质还是原来的 0.443 灰 / roughness 0.3 | §3.2 第 3 步 |
| 真实动作在 x 或 y 方向整体偏移 | 零件或挡条整体偏离标称位置，或者基座系标记画错了 | 用 §4.1 重新标记 |
| 策略在真机上总往同一个方向偏 | 相机在采集后被移动过 | §9.1 |
| 腕部画面时好时坏 | 线缆拉扯导致支架松动 | 加固支架，给线缆留出余量 |
| `communication_test` 的零力矩阶段机械臂自己往下掉，teleop 却正常 | 腕部相机和支架没有算进 Desk 的末端负载 | §7.2 |

- **§7.2 的负载修正**：机械臂下掉归因于相机重量，这是根据机器人读数推断的，还没有用取下相机或更新负载的方法验证过。如果更新后还掉，再查线缆拉扯。
